# Held-out test: HTTP links between Open edX services

A second answer key, built after the link finder was tuned on [Sentry](../sentry/README.md), to check whether its
rules generalise. The finder was frozen at commit `857f312` and run once against this key; the score below is that
first run, unchanged. Nothing in the finder was adjusted for Open edX before scoring.

## How it was made

1. For each repository, one agent listed every HTTP request its code sends to the other three, searching twice (by
   HTTP client usage, then by the settings and config names that point at the other services), and traced each one to
   the route and view that serve it, following `include()` chains, DRF routers and plugin URL configs. The agents
   could not see the link finder or its output.
2. A second pair of agents tried to refute every link: that production code really sends the request (base URL plus
   every path piece), that the method is right, and that the target's route and view serve exactly that method and
   path. 69 of 72 held; the other 3 are described below. Neither found a link the key lacked.
3. A script checked that every cited line exists at the pinned commits and mentions its path.
4. Rules fixed before the run: a request sent inside a library (the OAuth token request `edx_rest_api_client` makes)
   has no call site and is excluded; a route served only by an installed package (edx-search, edx-organizations,
   edx-proctoring, taxonomy-connector) is not in the target's source, so a call to it is listed under `no_route`,
   where a link from the finder counts as false; production operations scripts get their own scope, `ops`.

This is a machine-built and machine-checked key, not a human review.

### What this says

- The extractor knows a handful of URL-building idioms, the ones Sentry uses. Most real code builds URLs in ways it
  does not follow yet; data-flow through helpers, `urljoin`, `new URL()` and attributes is the largest gap.
- The base URL often carries a path (`…/api/v1`). Without reading settings values, a match has to allow the route to
  have a prefix the request lacks, and say so (inferred), instead of failing or matching a shorter route.
- The payload rule needs evidence that the URL leaves the service (it is put in a request body or a message), not just
  a `reverse()` call.
- Real bug found in Open edX while building the key: the platform asks course-discovery for `/api/v1/currency/`, but
  the route is `currency` with no trailing slash, so the request always gets a 404 and the platform silently gets an
  empty list (`openedx/core/djangoapps/catalog/utils.py:334`, `course_discovery/apps/api/v1/urls.py:42`).

Improvements to the finder should be scored on both keys, with this table kept as the held-out baseline.

## After the held-out fixes

The gaps above were fixed one at a time, each scored on both keys before the next; Sentry stayed at 20 / 20 with no
false link after every step. The fixes are general rules, not Open edX exceptions:

| Fix | Open edX production links | False links |
| --- | --- | --- |
| Frozen finder (`857f312`) | 12 / 71 | 31 |
| A `reverse()` URL is handed to another service only when it is made absolute (`base + reverse()`, `"{}{}".format(prefix, reverse())`, `urljoin`, `build_absolute_uri`) | 12 / 71 | 9 |
| A route of parameters only (`/{slug}`) does not take a request with fixed words; `swagger.{format}` takes `swagger.json`, not `accounts` | 12 / 71 | 3 |
| DRF routers (`router.register(...)`, list, detail and `@action` routes) and plugin URL configs (`plugin_app` in `apps.py`) | 19 / 71 | 3 |
| JavaScript: helpers that return a URL, `new URL(...).href`, `url.toString()`, function declarations | 36 / 71 | 3 |
| A route behind a short API prefix the base URL carries (`/api/v1`), preferred when the base is named as an API and preferring the prefix its name mentions | 60 / 71 | 0 |
| Configuration: `settings.NAME` and settings dicts, and the address book (settings, `.env` and docker-compose URLs: `localhost:port`, IPs, Docker DNS names, and the prefixes they carry) | 64 / 71 | 0 |
| Python: helpers and methods that return a URL (`self._make_studio_url(path)`), filled with the caller's arguments | **68 / 71** | **0** |

Of the 68, 44 are matched and 24 inferred (a route behind an assumed prefix). With SCIP, 8 are confirmed, 36 rest
on no name lookup, and the 24 inferred ones are not checked (SCIP confirms names, not which prefix a base URL has);
none is contradicted. The run takes about 10 seconds for the four repositories.
